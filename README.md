# Vigil

Offline-first astronaut health monitoring for the NASA Space Apps Challenge 2026
challenge, "Create Health Monitoring Software for Astronauts on Space Missions".

Vigil lets a crew member record health indicators and wellbeing check-ins, compare
each reading with their own pre-flight baseline and the expected early adaptation to
spaceflight, and act on evidence-linked alert cards with mission-aware escalation.
All crew data is simulated and clearly labeled. The app is decision support only and
is not a medical device.

## What is in the repository

- `src/contracts` - frozen types, indicator metadata, and app constants.
- `src/engine` - deterministic simulator, six scenarios, CUSUM detector, three
  detection systems, metrics, and the evaluation harness.
- `src/guidance` - reference ranges, measurement help, the fixed guidance library,
  alert-card construction, wellbeing rules, mission settings, and supplies.
- `src/storage` - IndexedDB persistence for measurements, check-ins, the journal, and
  settings.
- `src/app` - persisted application state, the services facade, routing, and demo
  helpers.
- `src/ui` - Today, domain detail, log, check-in, urgent help, Scenario Lab, Proof,
  Mission, Journal, and About screens.
- `public/data/results.json` - generated by `npm run harness` on evaluation seeds
  1-100 after the detector constants were frozen.

## Run it

Requires Node 20 or newer.

```bash
npm install
npm run dev
```

Production build and local preview:

```bash
npm run build
npm run preview
```

The PWA service worker precaches the app shell and `public/data/results.json`, so
after the first online load every screen works offline. Data stays in IndexedDB on
the device; "Reset demo data" clears it.

## Verify it

```bash
npm run typecheck
npm test
npm run build
npm run harness
```

`npm run harness` rewrites `public/data/results.json` and prints the evaluation
summary. Harness evaluation seeds are 1-100; tuning used seeds 1000-1099 only.

## Screens

- **Today** - body map, mission-day scrubber, six domain rows, alert cards, and the
  "Play demo story" button (crew 1, slow drift, deep space, day 120).
- **Domain detail** - indicator charts with the expected trajectory, baseline band,
  change marker, and measurement help; check-in trend for behavioral health.
- **Log** - guided manual entry with plausible-range validation and urgent callouts.
- **Check-in** - mood, stress, and energy sliders, optional note stored on device,
  support suggestions, and a direct urgent-help route.
- **Urgent help** - fixed emergency copy, with an extra line for deep-space transit.
- **Scenario Lab** - scenario and seed controls, three-system comparison, and alert
  cards for the scrubbed day.
- **Proof** - charts and tables rendered from `public/data/results.json`; no numbers
  are hardcoded in the UI.
- **Mission** - mission setting and supply checklist; changes persist and affect
  escalation, expected reply time, radiation expectations, and supply fallbacks.
- **Journal** - local investigation log with review filter and alert-card prefill.
- **About** - purpose, limits, sources, and the NASA HRP risk coverage map.

## Honest limits

- Every reading is simulated. Reference ranges, adaptation offsets, scenarios, and
  radiation rates are illustrative until a human verifies them.
- The detector is tuned on separate seeds from the evaluation, but it is still a
  prototype; the Proof page reports the real harness output, including cases where a
  baseline is better.
- The guidance library is fixed and sourced; it is not generated at runtime.
- No backend, accounts, network calls, LLM, or analytics run in the app.
- The four external clinical sources have `url: null` until a human verifies them;
  `docs/SOURCES_TODO.md` lists what is pending.
